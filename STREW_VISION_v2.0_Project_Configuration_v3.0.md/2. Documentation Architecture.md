# 2. Documentation Architecture

---

## 2.1 Purpose

STREW_VISION v2.0 설계 문서는 하나의 시스템을 여러 관점에서 설명하기 위해 계층적으로 구성한다.

모든 Volume은 명확한 책임(Responsibility)을 가지며, 동일한 내용을 여러 Volume에서 반복하지 않는다.

문서는 다음 세 가지 계층으로 구성된다.

- Foundation
- Platform Design
- Functional Design

---

## 2.2 Foundation

Foundation은 프로젝트 전체를 설명하는 문서이다.

프로젝트의 개발 목적과 시스템 전체 구조를 정의한다.

포함 Volume

- Volume01 Project Overview
- Volume02 System Architecture Design Specification

Foundation에서는 시스템 전체를 설명하며, 플랫폼 내부 구현은 설명하지 않는다.

---

## 2.3 Platform Design

Platform Design은 실제 프로젝트(Source Code)를 설명하는 문서이다.

Platform Design은 코드(as-is)를 기준으로 작성하며 실제 프로젝트 구조와 동일해야 한다.

포함 Volume

- Volume03 Arduino Mega Firmware Design
- Volume04 Jetson Nano Software Design
- Volume05 AWS Server & Dashboard Design

Platform Design에서는 다음 내용을 설명한다.

- Software Architecture
- Firmware Architecture
- Module Structure
- Class Structure
- Runtime
- Initialization
- Event
- Storage
- Cloud
- Configuration
- Integration

Platform Design은 프로젝트의 실제 구현 구조를 설명하는 것을 목적으로 한다.

---

## 2.4 Functional Design

Functional Design은 시스템 기능을 설명하는 문서이다.

기능의 목적과 역할, 전체 시스템에서의 동작 방식을 설명한다.

포함 Volume

- Volume06 ~ Volume20

Functional Design에서는 다음 내용을 설명한다.

- 기능 개요
- 목적
- 역할
- 데이터 흐름
- 운용 방식
- Example Scenario

Platform Design에서 설명한 구현(as-is)은 Functional Design에서 반복하지 않는다.

---

## 2.5 Documentation Relationship

세 계층은 다음 순서로 연결된다.

Foundation

↓

Platform Design

↓

Functional Design

Foundation은 시스템을 설명한다.

Platform Design은 프로젝트를 설명한다.

Functional Design은 기능을 설명한다.

각 계층은 서로의 책임을 침범하지 않는다.

---

## 2.6 Responsibility

각 Volume은 자신의 책임만 수행한다.

Volume 간 중복 설명을 금지한다.

예를 들어,

Platform Design에서 구현을 설명하였다면,

Functional Design에서는 동일한 구현을 다시 설명하지 않는다.

반대로,

Functional Design에서 기능을 설명하였다면,

Platform Design에서는 해당 기능의 목적을 반복 설명하지 않는다.

---

## 2.7 Documentation Principle

모든 설계 문서는 다음 원칙을 따른다.

- Foundation는 시스템을 설명한다.
- Platform Design은 프로젝트를 설명한다.
- Functional Design은 기능을 설명한다.
- 각 Volume은 자신의 책임만 설명한다.
- 이미 설명한 내용은 다른 Volume에서 반복하지 않는다.

이 원칙은 프로젝트 종료 시까지 변경하지 않는다.
