# STREW_VISION v2.0 Project Configuration
Version : 3.0
Status : Frozen

---

# 1. Project Purpose

## 1.1 Purpose

본 문서는 STREW_VISION v2.0 프로젝트의 설계 문서를 일관된 기준으로 작성하기 위한 Project Configuration이다.

모든 설계 문서는 본 문서를 최상위 기준(Source of Governance)으로 사용한다.

본 문서의 목적은 다음과 같다.

- 설계 문서의 일관성 유지
- Volume 간 역할 분리
- 중복 설명 방지
- 실제 코드(as-is)와 설계 문서의 일치
- 새로운 AI 세션에서도 동일한 프로젝트 상태 복원

---

## 1.2 Scope

Project Configuration은 다음 내용을 정의한다.

- 문서 작성 원칙
- Master Plan
- Volume별 책임
- 프로젝트 복원 절차
- 문서 작성 규칙
- 검증 절차

프로젝트 구현 방법이나 코드 자체는 정의하지 않는다.

---

## 1.3 Design Goal

본 프로젝트는 다음 목표를 가진다.

### 1. 설계와 구현의 일치

설계 문서는 실제 프로젝트 코드(as-is)를 기반으로 작성한다.

구현되지 않은 기능이나 추측은 포함하지 않는다.

---

### 2. Volume 간 중복 제거

동일한 내용을 여러 Volume에서 반복하지 않는다.

각 Volume은 자신의 책임 범위만 설명한다.

---

### 3. Platform 중심 설계

Platform Design 문서는 실제 프로젝트 구조를 설명한다.

Functional Design 문서는 기능의 역할과 목적을 설명한다.

---

### 4. 재현 가능한 프로젝트

새로운 GPT 세션에서도 동일한 프로젝트를 복원할 수 있도록 한다.

Project Configuration은 프로젝트 복원의 기준 문서가 된다.

---

## 1.4 Source of Truth

프로젝트의 최종 기준은 다음 순서를 따른다.

Priority 1

- Frozen Volume

Priority 2

- Notion Design Document

Priority 3

- Source Code (as-is)

Priority 4

- 사용자 승인 사항

Priority 5

- AI의 일반 지식

AI의 일반 지식은 프로젝트의 설계 기준보다 우선하지 않는다.

---

## 1.5 Project Principle

본 프로젝트는 다음 원칙을 따른다.

- 실제 구현(as-is)을 기준으로 작성한다.
- 추측하지 않는다.
- 이미 Frozen된 문서는 변경하지 않는다.
- Volume 간 책임을 변경하지 않는다.
- Master Plan은 프로젝트 종료 전까지 변경하지 않는다.

---

## 1.6 Final Goal

본 Project Configuration의 최종 목표는 다음과 같다.

- 프로젝트의 설계 철학을 유지한다.
- 새로운 AI 세션에서도 동일한 기준으로 프로젝트를 이어갈 수 있도록 한다.
- 모든 Volume을 하나의 통합 설계 문서(System Design Specification)로 완성한다.
