# 7. Writing Rules

---

## 7.1 Purpose

모든 설계 문서는 동일한 원칙으로 작성한다.

프로젝트 전체의 일관성을 유지하기 위해
모든 Volume은 본 규칙을 따른다.

---

## 7.2 General Rules

모든 문서는 다음 원칙을 따른다.

- 실제 프로젝트(as-is)를 기준으로 작성한다.
- 추측하지 않는다.
- 일반론보다 프로젝트 구조를 우선한다.
- 이미 설명한 내용을 반복하지 않는다.
- Volume의 책임을 벗어나지 않는다.

---

## 7.3 Platform Design Rules

Platform Design은

Volume03

Volume04

Volume05

를 의미한다.

Platform Design에서는

- Architecture
- Module
- Runtime
- Class
- Event
- Initialization
- Integration

등 실제 프로젝트 구조를 설명한다.

---

## 7.4 Functional Design Rules

Functional Design은

Volume06 ~ Volume20

을 의미한다.

Functional Design에서는

- 개념
- 목적
- 역할
- 데이터 흐름
- 운용 방식

만 설명한다.

Platform 구현은 반복하지 않는다.

---

## 7.5 Documentation Rules

모든 Volume은

다음 형식을 유지한다.

- Overview
- Background
- Purpose
- Architecture
- Data Flow
- Implementation
- Example Scenario
- Conclusion

필요하지 않은 항목은 생략할 수 있다.

---

## 7.6 Validation

문서를 작성하기 전에

다음을 확인한다.

□ Master Plan

□ Volume Responsibility

□ Frozen Decision

□ 기존 Volume

□ 실제 Source Code

---

## 7.7 Principle

설계 문서는

프로젝트를 설명하는 문서이다.

논문처럼 작성하지 않는다.

실제 구현과 일치하는 것이 가장 중요하다.
